# ДЗ 8–10: выпуск модели и локальный API

Процесс выпуска на Prefect, HTTP API на FastAPI, семь исправленных причин ошибок.
Используются готовые модель и полный eval из ДЗ 6–7. Нового обучения нет.

- **57 проверок проходят**: 13 исходных, 6 дополнительных, 7 интеграций на каждом
  из двух адаптеров и 24 прежних теста.
- Одни и те же семь интеграционных тестов обнаруживают дефекты исходного прототипа.
- Настоящий API повторил **53/53** сохранённых ответа baseline.
- Кандидат отклонён прежним quality gate; сервис загружает закреплённую baseline.
- Проверены кеш, восстановление, повтор выпуска, A → B → A и реальный перезапуск.
- Замер **8+8**: 16 успешных запросов, средняя задержка 0,709 / 1,316 с.

## Проверки

Python 3.12. Команды из этого каталога:

```bash
make install            # uv sync --frozen, окружение без загрузки весов
make check              # полный прогон 57 проверок, около минуты
make status             # проверка сохранённых результатов, raw-ответов и SHA-256
make prove              # те же 7 тестов: исходник → исправление → Prefect/FastAPI
make break-demo         # намеренная поломка в отдельной копии; тесты дают exit 1
```

`make break-demo` завершает свой демонстратор успешно после обнаружения поломки;
настоящий ненулевой код тестов записан в `evidence/checks/intentional-failure.txt`.
Рабочая версия не меняется. Быстрые проверки не загружают модель.

При новом выполнении опытов рабочие каталоги и новые результаты создаются
параметрами `--workspace` / `--output`; предыдущие файлы сохраняйте.
Для обновления экспортированных результатов после повторных проверок — `make export`.

## Настоящий API

На этом Mac окружение и артефакты уже подготовлены. В первом терминале:

```bash
make serve
```

Во втором, после прогрева:

```bash
make health
make predict
make invalid
make gate
make status
```

API: `http://127.0.0.1:8091/docs`. Во время загрузки `/ready` возвращает 503,
после прогрева — 200. Остановка сервера — Ctrl+C в первом терминале.
Если порт занят: `make serve PORT=9091`, а клиентские команды выполняйте с `PORT=9091`.

`make gate` заново проверяет файлы и полный допуск; наш кандидат получает REJECT
и ненулевой код. Принятая baseline остаётся прежней. Через весь Prefect-flow:
`make release` с тем же ожидаемым отказом. Принятый указатель не меняет модель
в памяти: для загрузки нового принятого manifest требуется перезапуск сервера.

Для повторного замера при работающем API:

```bash
.venv/bin/python scripts/benchmark.py --n 8 --output evidence/benchmark-repeat
```

Исходные 8+8 сохранены в `evidence/benchmark`. Скрипт не перезаписывает
существующий каталог и сохраняет ошибки/тайм-ауты вместе с успешными запросами.

## Воспроизведение и доступ к артефактам

```bash
make install-model
make fetch-base         # только если точной базы ещё нет в локальном HF-кеше
make prepare-real       # реальные хеши файлов и импорт закреплённой baseline
make smoke              # реальный ответ и проверка readiness/неверного запроса
```

Публичная база: [Qwen/Qwen3-0.6B, точная revision](https://huggingface.co/Qwen/Qwen3-0.6B/tree/c1899de289a04d12100db370d81485cdf75e47ca).
Inventory файлов — `config/base-files.json`. В Git весов нет.

Адаптер: готовый training run `1efd3e7eeda54bfc9ee161cf28065807`,
`models:/pandas-qwen-adapter/1` в MLflow предыдущей работы на этом Mac.
При работающем старом MLflow: `make fetch-candidate`, затем `make prepare-candidate`.
Это получение готового результата, обучения нет.

Для передачи преподавателю подготовлен отдельный архив
`.runtime/distribution/pandas-candidate.tar.gz` (22 462 355 байт).
Его SHA-256 и хеши всех файлов — в `config/candidate-artifact.json`.
Архив передаётся отдельно от Git либо публикуется как Release asset вместе с репозиторием.
Восстановление из полученного архива:

```bash
.venv/bin/python scripts/restore_candidate.py /path/to/pandas-candidate.tar.gz
make prepare-candidate CANDIDATE_DIR=.runtime/artifacts/restored-candidate
```

Без адаптера доступны запуск публичной baseline и проверка полного сохранённого eval;
повтор загрузки кандидата требует указанного архива или старого MLflow.
Локальные URI в manifest пересоздаются на другом компьютере; хеши файлов,
базы, runtime и оценки должны совпасть с inventory.

## Файлы

| Файл | Назначение |
|---|---|
| `release.py`, `journal.py` | Контракт допуска, атомарная запись, события, восстановление, откат |
| `preparation.py`, `flow.py`, `flow_lab.py` | Подготовка с кешем и задачи Prefect; совместимый STUB-запуск |
| `api.py`, `api_core.py`, `backends.py` | FastAPI, валидация, очередь, готовность, настоящая модель и stub |
| `lineage.py`, `materialize.py` | Связь training run → полный eval → решение → загруженные файлы |
| `tests/`, `integration/`, `verification/` | Исходные, собственные интеграционные и дополнительные тесты |
| `previous/hw67/`, `previous/source.json` | Прежняя сдача и SHA-256 её неизменённых файлов |
| `evidence/` | Настоящие журналы, raw-ответы, замер, manifest и SHA-256 |
| `docs/report.md`, `defects.csv` | Единый отчёт и семь независимых причин |

STUB-артефакты помечены `STUB ONLY`; их опыты проверяют процессы и HTTP.
Настоящие ответы модели сохранены отдельно. Веса, среды Python, рабочие каталоги,
кеши, Docker-volumes, секреты и видео исключены из Git. CI выполнен локально;
`ci.example.yml` — шаблон, удалённый CI и защита merge не заявляются.
