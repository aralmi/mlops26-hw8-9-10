# Незавершённые этапы перед сдачей

Код подготовлен без исполнения. Этот список описывает техническую проверку,
а не сценарий записи и не журнал успешно выполненных работ.

- [ ] `make lock`: проверить совместимость зависимостей, сохранить новый `uv.lock`.
- [ ] `make install`: лёгкое окружение; убедиться, что torch не требуется.
- [ ] `make check`: исходные 13, свои интеграции на двух адаптерах, устойчивость, прежние тесты.
- [ ] `make prove`: семь падений свойств на исходнике и зелёный целевой прогон.
- [ ] `make break-demo`: намеренная поломка обнаружена, рабочая версия цела.
- [ ] `make process-demo`: новые процессы, cache hit, инвалидация, восстановление журнала.
- [ ] `make versions-demo`: фактически загруженные STUB A → B → A через HTTP.
- [ ] `make install-model`: проверить те же версии библиотек, что в предыдущей оценке.
- [ ] `make prepare-real`: реальный SHA-256 весов и всех файлов baseline, provenance без fake PASS.
- [ ] `make fetch-candidate`: экспорт прежнего артефакта из существующего MLflow, без sweep.
- [ ] `make prepare-candidate` и `make release`: реальный REJECT с прежними байтами указателя.
- [ ] Сохранить `.runtime/release-report.json`, manifest, baseline-import и хеши указателя в evidence.
- [ ] `make smoke`: реальная загрузка, warmup, ответ, invalid 422, совпадение с eval.
- [ ] `make serve`, `make replay`: все 50+3 ответа, затем остановить сервис либо продолжить замер.
- [ ] `make benchmark`: 8+8 запросов; при необходимости явно выбрать 4+4.
- [ ] Снять секреты/локальный мусор со списка публикации; проверить размер файлов.
- [ ] Заменить отметки PENDING в defects.csv настоящими ссылками на полученные журналы.
- [ ] Заполнить отчёт измерениями, финальными commits и ссылкой на репозиторий.
- [ ] Подготовить одно видео 5–8 минут после подтверждённых запусков.

Не менять старые ответы и условия gate ради успешного выпуска.
Если реальная генерация отличается от сохранённого eval — сначала найти
причину расхождения; при изменённых условиях потребуется новая полная оценка.
