# ДЗ6–7: поиск LoRA-конфигурации и проверка выпуска

Продолжение [ДЗ4](https://github.com/aralmi/mlops26-hw4) и
[ДЗ5](https://github.com/aralmi/mlops26-hw5) на собственных вопросах pandas.
Шесть коротких экспериментов MLflow, один candidate и сравнение его ответов
с базой перед решением о champion. Итог — в [docs/conclusion.md](docs/conclusion.md).

## Исправления и данные

Четыре дефекта: отдельные nested runs вместо общего, постоянный volume для
артефактов, версии train/val в каждом run и проверка loss-порога до регистрации.
Подробности — [docs/defects.md](docs/defects.md).
Scorer и gate — в `evaluation/solution.py`. Исходные tests не менялись:
**c42ac7788026**.

Вход — побайтово те же тензоры ДЗ4, **1388 train / 154 val**, max length 3456.
SHA256, исходный коммит и проверка повторной токенизации всех 1388 train
с точным совпадением токенов и масок — `docs/data-lineage.json`.

Поиск: CPU float32, seed 42, **6 × 4 шага**, train-пул 32, val 8,
batch 1 × accumulation 2. Меняются lr, r, target_modules. Это бюджет
стартового задания, не полное обучение на 1388 примерах.

Golden — 50 новых задач по коду pandas, пять срезов по 10 вопросов.
Эталоны проверены исполнением pandas 2.3.3. Индекс train содержит все
1388 исходных вопросов, не только пул поиска. Нормализованных совпадений
и общих group_id нет; это не исключает любых смысловых перефразов.
Три behavioral-кейса: формат, перефраз и отказ вне темы. Они не увеличивают n golden.
Протокол и критические срезы закреплены до оценки в `docs/protocol.md`.

Данные версионируются DVC. Доступная копия — **submission/evaluation-data.zip**:
разметка, вопросы оценки, полный текстовый индекс train и атрибуция.
В архиве нет весов и токенизированных тензоров. Источники — `DATA_LICENSE.md`.

## Окружение

Нужны Python 3.12, uv, Git и работающий Docker Desktop.

```bash
uv sync --frozen
```

Перед первым запуском создайте `.env` по `.env.example` и задайте
свой локальный буквенно-цифровой пароль PostgreSQL. `.env` исключён из Git.
PostgreSQL не публикуется на хост, MLflow доступен только на
**http://127.0.0.1:5006**. Не запускайте второй сервер на том же порту.

```bash
make up
```

`make down` сохраняет volumes. Не выполняйте `docker compose down -v`,
если нужны накопленные runs и адаптеры.

## Полное воспроизведение

Если рядом есть собственное ДЗ4 в `../../mlops26-hw4/hw4-broken`
с исходными данными, точным коммитом и токенизатором в HF cache:

```bash
make prepare-data
make status
make check-eval
make verify
make up
make sweep
make report
make candidate
make baseline-init
make evaluate
make eval
```

`make sweep` обучает заново. Для просмотра готовой работы его повторять
не нужно. `baseline-init` выполняется однократно и запрещает перезапись.
После нового sweep оцените нового candidate, не используйте старые ответы.

`make eval` возвращает ненулевой код при отказе — это допустимый результат,
который нельзя подавлять или превращать в PASS. Увеличивать бюджет и менять
порог ради выпуска задание не требует.

После оценки:

```bash
make check-negative
```

Только при PASS выполните `make promote`. При отказе champion не создаётся
или остаётся прежним; candidate доступен для загрузки. Baseline автоматически
не заменяется. В обоих случаях дальше:

```bash
make check-storage
make submission
make check-all
make verify
```

Хранение проверяется реальным пересозданием только контейнера MLflow и SHA256
скачанного probe. `check-all` — девять проверок MLflow и 24 теста оценки;
`verify` — восемь дополнительных unit-тестов. Синтетические фикстуры тестов
не заменяют реальные ответы модели.

## Доступ на другом компьютере

Local DVC remote `../dvc_remote` не публикуется на GitHub. Если он передан
отдельно, выполните `uv run dvc pull`. Без него данные оценки восстанавливаются
из приложения:

```bash
uv run python -m preparation.restore_eval
```

Команда сверяет SHA256 архива и не перезаписывает отличающиеся файлы.
Тензоры ДЗ4 нужно получить из своего пайплайна; адаптеры находятся в
MLflow volume, базовые веса — в HF cache. Свежий Git-клон не содержит
работающий сервер и обученные модели. Сохранённые результаты можно читать
без них: `docs/results/`. Ссылки на runs ведут на локальный, не публичный сервер.

## Материалы сдачи

- `docs/comparison.csv` — шесть runs, значения из MLflow API.
- `docs/defects.md` — причины и исправления.
- `docs/conclusion.md` — выбор, срезы, ответы, ограничения и решение о выпуске.
- `docs/results/` — raw-ответы, отчёты, diff, gate, отрицательная проверка,
  storage proof, состояние alias и параметры/кривые runs со ссылками.
- `docs/check-all.txt`, `docs/verify.txt` — фактический вывод проверок.
- `eval-data.dvc`, `tokenized.dvc`, `.dvc/config` — версии данных.
- `evaluation/baseline.json`, `evaluation/params.json` — закреплённые версии.
- `submission/evaluation-data.zip` — доступное приложение с данными проверки.

Сдаются ссылка на репозиторий с коммитом и **одно видео 5–8 минут**:
шесть runs, candidate, оценка, отрицательная проверка, состояние champion,
хранение и тесты. Веса, тензоры обучения, окружение, кэши, volumes и
`.env` не входят в Git или приложение.
